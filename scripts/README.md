# Evaluation scripts and regression tests

All inference/evaluation entrypoints live in this directory. Training remains
at `main.py` in the repository root. The former top-level `tests/` has moved
to `scripts/tests/`; its regression checks are retained.

```text
main.py                         # Training entrypoint (repository root)
scripts/
  run_inference.py               # Recommended manifest-based evaluation runner
  infer_retrieval.py             # Test-split retrieval and re-ranking
  infer_generation.py            # Molecular generation and re-ranking
  infer_mlm.py                   # Auxiliary masked-SMILES reconstruction
  infer_retrieval_pubchem.py      # External candidate-library retrieval
  infer_retrieval.sh             # Legacy batch retrieval script
  infer_generation.sh            # Legacy batch generation script
  test_mmm.sh                    # Four-checkpoint MMM acceptance workflow
  configs/                      # Experiment YAML manifests
  tests/                        # CPU regression tests
```

## CPU regression tests

From the repository root, run:

```bash
python -m unittest discover -s scripts/tests -v
```

These checks use synthetic data and tiny random models, not downloaded datasets,
checkpoints or a GPU. They cover LMDB sample order, candidate alignment, model
compatibility, manifest paths, and direct/module CLI startup. They do not measure
trained-model accuracy; use the inference suites below for that.

## Inference experiment runner

The YAML manifests in `configs/` specify entrypoints, dataset/checkpoint paths
and inference settings. Run from the repository root.

```bash
python scripts/run_inference.py retrieval --list
python scripts/run_inference.py retrieval qm9s_ir qm9s_raman --dry-run
python scripts/run_inference.py retrieval --dataset qm9s --device cuda:0 --batch-size 32
python scripts/run_inference.py generation qm9s_ir_raman_formula --device cuda:0 --batch-size 32
```

Select experiment names, `--dataset`, or `--all`, not a combination. `--list`
does not need artifacts. `--dry-run` checks local dataset/checkpoint paths but
does not execute the model. The runner uses the same Python interpreter as the
parent process, runs from the repository root, and stops on an experiment error.

For custom options, invoke the underlying scripts from the repository root:

```bash
python scripts/infer_retrieval.py --help
python scripts/infer_generation.py --help
python scripts/infer_mlm.py --help
python scripts/infer_retrieval_pubchem.py --help
```

Module execution also works, for example `python -m scripts.infer_retrieval --help`.
Direct Python entrypoints preserve the working directory; relative data,
checkpoint and tokenizer paths are resolved from it. Do not run them from inside
`scripts/`. Replace old root-level `infer_*.py` commands with `scripts/infer_*.py`;
manifest-runner and `scripts/test_mmm.sh` commands are unchanged.

## Suites

| Suite | Model and purpose |
| --- | --- |
| `retrieval` | Vib2Mol test-split retrieval and matching re-ranking |
| `generation` | Vib2Mol greedy/beam generation and optional formula filtering |
| `retrieval_mmm` | MMM full-modality and masked-modality retrieval |
| `generation_mmm` | MMM generation |
| `mlm` | Final Vib2Mol masked-SMILES reconstruction, not a separate MLM model |
| `pubchem` | MMM retrieval against an external candidate library |

`retrieval --employ-mmm` is a compatibility alias for `retrieval_mmm`.
Missing artifacts cause a clear error; MMM checkpoints and the PubChem
embeddings/dataframe are not included in the standard test bundle.

MLM branch reconstruction evaluates every branch occurrence by default. To
evaluate each distinct branch text only once per SMILES:

```bash
python scripts/run_inference.py mlm mols_raman_vib2mol --deduplicate-branches
```

PubChem candidate embeddings must have been generated by the same compatible
molecular encoder as the retrieval checkpoint, and their row order must match
the candidate dataframe. Do not substitute weights without regenerating that
index. Use only trusted pickle dataframes.

## Four-checkpoint MMM test bundle

Extract the MMM test bundle directly into the existing repository root. It
contains current code, tokenizers, and exactly four MMM checkpoints (QM9S/MOLS,
retrieval/generation); datasets, standard-model checkpoints, and original
`logs/` and `runs/` are not included or removed. The MOLS manifests use the
current `checkpoints/mols/` paths.

The VPS needs `datasets/vibench/qm9s/qm9s_test.lmdb` (12,982 records) and
`datasets/vibench/mols/mols_test.lmdb` (37,570 records). If needed, download only
these test files from the repository root:

```bash
hf download xinyulu/vibench qm9s/qm9s_test.lmdb mols/mols_test.lmdb --repo-type dataset --local-dir ./datasets/vibench
```

On Linux, verify the four transferred checkpoint files and launch the tests:

```bash
sha256sum -c scripts/mmm_checkpoints.sha256
CUDA_VISIBLE_DEVICES=0 bash scripts/test_mmm.sh
```

The script checks paths, runs CPU unit tests, and performs eight full evaluations:
IR-only/Raman-only/IR+Raman retrieval and IR+Raman+formula generation, for each
dataset. Both tasks include matching re-ranking. Each invocation creates a new
`test_outputs/mmm.*` directory and stops on failure. It excludes SDBS/PubChem,
whose required artifacts are not in this bundle.

To test one dataset or reduce GPU memory use:

```bash
CUDA_VISIBLE_DEVICES=0 bash scripts/test_mmm.sh qm9s
CUDA_VISIBLE_DEVICES=0 VIB2MOL_BATCH_SIZE=16 bash scripts/test_mmm.sh mols
```

Retrieval constructs a dense similarity matrix on CPU. The full MOLS matrix
alone occupies about 5.65 GB in float32, with additional RAM needed for records,
ranking and model weights. Reducing batch size does not reduce that matrix.

All four packaged checkpoints pass strict parameter loading against the
181-output, two-channel MMM model and contain finite floating-point tensors.
These are compatibility checks, not a claim of full GPU metric validation.

See the root [README](../README.md) for installation and other evaluation
entrypoints. The `scripts/infer_*.sh` scripts are legacy entrypoints; prefer the
manifests for new evaluations.
